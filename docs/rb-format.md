# RogueEngine RB format\n\nRogueEngine .rb is the native editable asset container. Version 2 is a chunked binary envelope designed to preserve editable RogueEngine data instead of flattening everything to a final GLB.\n\n## Header\n\nThe header is 12 bytes:\n- offset 0: 4-byte magic RRB1 (`0x31425252`)\n- offset 4: uint32 version, little-endian (`2`)\n- offset 8: uint32 chunk count, little-endian\n\nEach chunk is:\n- uint32 type, little-endian\n- uint32 payload size, little-endian\n- raw payload bytes\n\nAll integer fields in the format are explicitly little-endian. Float32 values are IEEE-754 binary32 bit patterns encoded as little-endian uint32 values. Float64 values are IEEE-754 binary64 bit patterns encoded as little-endian uint64 values. The implementation does not depend on host endianness.\n\n## Version 2 chunk families\n\n- MANF — format/version/name manifest\n- GLVB — reserved for a GLB base payload\n- SSCN — scene nodes, source metadata, and skin bindings\n- MRPH — morph channels, dense/sparse shape keys, slider ranges, categories, body parts, and morph drivers\n- RIGS — armatures, bones, rest transforms, and constraints\n- ANIM — animation clips, channels, keys, and values\n- PHSY — reserved for physics data\n- VSRE — reserved for Verse data\n- TXTR — embedded named binary blobs, currently used for texture/embedded data\n- MDAT — native metadata bytes\n\n## MRPH payload\n\nMRPH begins with a uint32 morph_channel_count. Each morph channel contains: name, category, body_part, and shape_key_count. Each shape key contains a UTF-8 name followed by a uint8 storage flag: 0 = Dense, 1 = Sparse.\n\nDense storage: uint32 float_count followed by float32 position_deltas[float_count]. float_count must be divisible by 3 and values are XYZ triplets.\n\nSparse storage: uint32 delta_count followed by delta_count records. Each record is uint32 vertex_index followed by float32 dx, dy, dz.\n\nBoth forms then store float32 weight, slider_min, slider_max, followed by string category and body_part. Drivers follow with target, expression, variables, and each variable's name, source, and float32 scale.\n\nThe sparse representation stores only vertices affected by a morph. This is a storage optimization; the eventual GPU runtime may repack sparse data into a backend-appropriate dense/packed buffer.\n\n## String encoding\n\nA string is a uint32 UTF-8 byte length, little-endian, followed by UTF-8 bytes without a terminating null.\n\n## Safety\n\nThe reader validates the outer RB container before parsing chunks, applies count and bounds limits to nested arrays, verifies skin-binding index/weight lengths, verifies dense morph data is composed of XYZ triplets, rejects unknown morph storage flags, and rejects malformed chunk payloads or trailing bytes.\n\n## Current state\n\nVersion 2 round-trips the currently defined AssetDocument scene, dense/sparse morph, rig, constraint, animation, embedded-blob, and metadata fields. GLVB, PHSY, and VSRE remain reserved until their corresponding systems are implemented.
